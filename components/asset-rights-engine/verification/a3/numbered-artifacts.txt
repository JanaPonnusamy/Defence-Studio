   1: # Contracts v1
   2: 
   3: All inputs are frozen dataclasses. Stable identifiers use 1–128 ASCII letters, digits,
   4: underscore, period, colon or hyphen, beginning with a letter or digit. SHA-256 fields
   5: require exactly 64 lowercase hexadecimal characters. Revisions are positive integers;
   6: expected initial rights revision alone is zero. Timestamps must carry an explicit UTC
   7: offset. Evaluation uses caller-supplied time, never an implicit wall clock.
   8: 
   9: AssetDescriptor metadata_version=1 supports image/video/audio/graphic/other. Name,
  10: provenance, original source and creation/registration timestamps are required. Media
  11: bytes, file existence and verification are never assumed. Known MIME must be compatible
  12: with image/video/audio categories; size is a nonnegative integer. VALID means metadata
  13: contract validation only. Registered descriptors are immutable; corrections use a new ID.
  14: 
  15: RightsRecord contract_version=1 states: UNKNOWN, PENDING_REVIEW, APPROVED, REJECTED,
  16: EXPIRED, REVOKED. Persisted input APPROVED is rejected. Successful review creates a
  17: separate approved review state over immutable pending content. Explicit rights basis,
  18: licence name and evidence notes are required for approval. Custom licence names are
  19: accepted as declarations, not interpreted as a known licence. URLs are inert strings.
  20: Permissions and attribution requirement are tri-state Boolean/unknown. Unknown required
  21: permissions block; false permissions block requested operations. A required attribution
  22: must exactly match the declared text. Territory restrictions use uppercase two-letter
  23: codes; omission of a territory blocks a restricted grant. Empty territory list declares
  24: no territory restriction. Valid-from is inclusive; valid-until is exclusive.
  25: 
  26: UseContext records commercial, modification, distribution, territory, attribution text
  27: and evaluated_at. Unrequested modification/distribution need no permission. Record
  28: approval never implies a permission. An evaluation before its rights review blocks.
  29: 
  30: SceneBinding carries host_application, job_id, scene_id, plan_version, plan_sha256 and
  31: optional content_digest. All fields participate in exact binding comparison. The host
  32: must supply its authoritative approved plan. The core cannot authenticate that assertion.
  33: AssignmentDescriptor contract_version=1 carries binding, asset ID, role, use context,
  34: rights revision/hash and state. Assignment revision and identity live in RevisionView.
  35: DRAFT/PENDING_REVIEW/BLOCKED may be supplied at creation or revision. APPROVED requires
  36: review. A changed rights revision yields derived STALE. A changed scene plan produces
  37: STALE_SCENE_BINDING at evaluation, without mutating or rebinding the historical record.
  38: 
  39: Every decision requires a nonempty note. First decision per entity revision wins;
  40: additional decisions require a new revision. Idempotency keys are unique across all
  41: review kinds. Their payload includes binding and usage context. Exact replay returns
  42: one original event; all other reuse conflicts. Reviews reference content digests and
  43: expected revisions. Approval of blocked assignments is refused.
  44: 
  45: Evaluation returns eligibility, blocker codes, warnings, human actions, rights revision,
  46: rights hash and deterministic timestamp. Readiness requires current approved rights,
  47: compatible use, exact scene binding, current assignment approval, and matching usage.
  48: Only evaluated_at may change without creating a new assignment revision. Readiness always
  49: warns MEDIA_AVAILABILITY_UNVERIFIED; it is rights readiness, not render readiness.
  50: 
  51: The exported pure evaluator accepts an optional immutable ReviewEvent, checks decision,
  52: revision, digest and time, and defaults to blocked without review evidence. For an
  53: untrusted caller always use Engine.evaluate_effective_rights, which loads its own history.
  54: Passing fabricated events to the pure function has no effect on persisted approval.
  55:

   1: # Architecture
   2: 
   3: contracts.py defines validated immutable input contracts and structured results/errors.
   4: evaluator.py is a deterministic pure metadata evaluator. engine.py provides transactional
   5: SQLite persistence, version selection, explicit review workflows and readiness.
   6: __init__.py is the public integration surface. schema.sql is packaged runtime migration
   7: 001; migrations/001_initial.sql is its reviewable source mirror. scripts/ contains an
   8: administrator initialization/snapshot CLI and a synthetic temporary-database example.
   9: Tests use unittest and temporary directories, with no paid or network services.
  10: 
  11: ## Database v1
  12: 
  13: assets stores immutable metadata JSON. rights_revisions stores immutable versioned
  14: rights JSON/hash keyed by asset/revision, with a foreign key to assets. assignments
  15: stores identity and an asset foreign key. assignment_revisions stores versioned binding,
  16: usage and rights references. review_state holds the latest decision per kind/entity;
  17: review_history holds reviewer, decision, note, revision, digest, timestamp, idempotency
  18: key and canonical full request. migrations holds version, application timestamp and
  19: SQL checksum. PRAGMA user_version is 1. Assets/revisions/history/migration records are
  20: protected by update/delete triggers. Media bytes are never stored.
  21: 
  22: Each operation opens/closes its own connection. Foreign keys are enabled on every
  23: connection. BEGIN IMMEDIATE serializes writes; expected revisions and first-review
  24: checks reject concurrent conflicts. Read operations use one snapshot transaction for
  25: consistent readiness across concurrent changes. Parameterized values are used throughout;
  26: dynamic SQL identifiers come exclusively from fixed internal table names.
  27: 
  28: ## Migrations
  29: 
  30: Version 0 with no tables migrates atomically to version 1. Existing unversioned tables
  31: are rejected without modification. Initialization reruns validate the packaged migration
  32: checksum and integrity instead of overwriting data. Unknown future versions fail closed.
  33: Future releases must add numbered, additive migration scripts and sequential transactional
  34: upgrade steps; never edit migration 001 or rewrite historical rows. No later migrations
  35: are shipped in Phase A1. Backup before upgrades. Both mirror and packaged SQL must match.
  36: 
  37: Snapshots use sqlite3.Connection.backup, including committed WAL content, and reject
  38: existing destination files. Restore by constructing Engine in the configured directory
  39: with the snapshot basename, or copying a completed offline snapshot to another trusted,
  40: dedicated directory. Never copy only a live WAL database file as a backup.
  41: 
  42: ## Future host adapter
  43: 
  44: The adapter belongs in the host, not this package. It must translate an authoritative
  45: approved host plan into SceneBinding, identify authenticated reviewers, select trusted
  46: component-owned data storage, translate usage into UseContext, and call readiness with
  47: the current binding immediately before use. Changed plans require explicit assignment
  48: revision and fresh review; changed rights require explicit reassignment to the current
  49: rights revision. The adapter handles media resolution/verification and host permissions.
  50: The core never imports host scene classes or connects to the host database. No integration
  51: with Defence Studio, QVault or Whisper Studio has been performed.
  52: 
  53: ## ARE-A2 optional boundary
  54:

   1: # Security and isolation
   2: 
   3: No external calls, fetching, downloading, media execution or automatic file opening.
   4: Runtime dependencies are Python standard library only. Metadata references are inert.
   5: The database lives under an explicitly configured trusted component-owned directory;
   6: database and snapshot basenames cannot be absolute, traverse directories, or resolve
   7: through a symlink outside that root. Configuration paths are administrator inputs, never
   8: asset metadata. Tests explicitly supply isolated temporary directories.
   9: 
  10: Approval is an explicit persisted review action. Input APPROVED flags are rejected;
  11: first decision, expected revisions, digests and idempotency payloads are checked within
  12: one write transaction. Relevant rights or assignment revisions invalidate readiness.
  13: Scene plan changes are detected only when the adapter supplies the new authoritative
  14: binding. History is append-only under normal SQLite writes via immutable triggers.
  15: 
  16: The caller must authenticate reviewers and constrain data-directory configuration.
  17: This library is not a multi-tenant authorization system. An administrator with direct
  18: filesystem/SQLite access can remove triggers or alter records; there is no cryptographic
  19: signature or external tamper-proof ledger. SQLite integrity, foreign keys, stored hashes
  20: and required triggers are validated, but this is not protection against a privileged
  21: attacker. Filesystem race resistance against hostile local users is not guaranteed.
  22: Protect the configured directory with operating-system permissions.
  23: 
  24: Rights decisions evaluate declarations, not law, ownership or real-world evidence.
  25: No media-availability claim is made. There is no REST server, media verifier, licence
  26: catalogue or automatic rights inheritance. Backup destinations must be unused; a failed
  27: backup may leave a partial new destination, which must not be used until validated.
  28: 
  29: ## ARE-A2 trust boundary
  30: 
  31: Validated DTOs and host approval/principal assertions are not authenticated evidence.
  32: AdapterGateway requires a supplied HostAdapter implementation, but cannot certify it.
  33: Production must authenticate sessions, authorize operations/resources, enforce tenant/owner
  34: mappings and keep authoritative plan state stable before/through the engine operation.
  35: No Engine authorization callback or real host authentication is implemented. Direct core

  37: 
  38: SyntheticHost grants are in-memory test policy only, never real authorization. The simulator

   2: 
   3: ARE-A2 supplies a framework-neutral Python Protocol, validated immutable DTOs, an
   4: optional gateway, and a deterministic offline simulator. It is not a production adapter,
   5: authentication system, tenant-aware database or rights/ownership verifier.

   7: ## Import and operations
   8:

  11:     HostScope, HostSceneKey, HostSceneContext, HostPrincipal, PlanState, HostOperation
  12: )
  13: from asset_rights_engine.host_adapter import HostAdapter, AdapterGateway
  14: 
  15: # engine: existing ARE-A1 Engine in a trusted component-owned directory
  16: # trusted_host: a production implementation of the Protocol described below
  17: # Do not populate these from public request flags alone.
  18: # gateway = AdapterGateway(engine, trusted_host)
  19: ```
  20: 
  21: The gateway exposes create_assignment, revise_assignment, review_rights,
  22: review_assignment and evaluate_assignment_readiness. Every operation takes the expected
  23: HostSceneContext and HostPrincipal. Assignment operations additionally take both the
  24: internal assignment_id and internal asset_id; these are checked against host mappings
  25: and engine content, never derived from host scene identifiers. Other parameters retain
  26: the corresponding ARE-A1 meaning. Rights/assignment reviews accept the existing
  27: ReviewRequest, and require request.reviewer to equal principal.principal_id. The gateway
  28: calls actual Engine APIs and does not duplicate rights evaluation or persistence.
  29: 
  30: Importing `asset_rights_engine` continues to expose ARE-A1 names and does not import
  31: adapter or simulator modules. Explicitly import the optional submodules when needed.

  33: ## DTOs and validation
  34: 
  35: | Contract | Required fields |
  36: |---|---|
  37: | HostScope | host_application, tenant_id, owner_id |
  38: | HostSceneKey | HostScope, host-scoped job_id, stable scene_id |
  39: | HostSceneContext | scene key, positive integer plan_revision, lowercase SHA-256 plan_sha256, PlanState, strict Boolean host_asserts_approved |
  40: | HostPrincipal | HostScope and nonempty principal_id; an identifier only |
  41: | HostOperationRequest | operation, expected_context, principal, internal asset_id, assignment_id except for rights review |
  42: 
  43: Identifiers follow ARE-A1's stable identifier rules. Booleans are not revisions.
  44: HostSceneContext optionally carries scene_content_digest and contract_version=1.
  45: PlanState is DRAFT, PENDING_REVIEW, APPROVED or REVOKED. The approval assertion must
  46: be true exactly when state is APPROVED; contradictory states are rejected. Missing
  47: or malformed hashes never create a valid context. A structurally valid draft context
  48: can be represented, but all gateway operations require a currently asserted approved
  49: plan. Its scene_binding method translates approved metadata into ARE-A1 SceneBinding:
  50: plan_version is the decimal positive revision string. This adapter contract deliberately
  51: uses integer plan revisions; ARE-A1 still accepts opaque plan-version identifiers.
  52: 
  53: Tenant/owner fields are host authorization scope, not new SQLite columns or substitutes
  54: for engine asset/assignment IDs. They are not encoded into ARE-A1 scene IDs. Use trusted
  55: resource mappings and dedicated engines/storage per scope; equal job/scene IDs in another
  56: tenant do not imply shared identity. No implicit tenant isolation is added to Engine.
  57: 
  58: ## Three distinct trust levels
  59: 
  60: 1. **Validated:** constructing a DTO checks syntax, type, revision, digest and consistent
  61:    assertions. It does not inspect a host or authenticate anybody.
  62: 2. **Host asserted:** DTO approval/principal fields describe a host's claim. A Boolean,
  63:    principal string or even a matching scope is not proof of authority.
  64: 3. **Authenticated and authorized:** the future production host must obtain identity
  65:    from its authenticated session, authorize the exact operation and resource, enforce
  66:    ownership/tenant scope, and read its authoritative approved plan before invoking the
  67:    engine. No implementation of this level ships in ARE-A2.
  68: 
  69: HostAdapter has one structural method:
  70: 
  71: ```python
  72: def operation_context(request: HostOperationRequest) -> AbstractContextManager[HostSceneContext]:
  73:     ...
  74: ```
  75: 
  76: The provider must reject unauthorized operations before yielding. It must independently
  77: check principal/session correspondence, permissions, host/job/scene ownership, asset
  78: ownership, immutable assignment-to-scene/asset mappings and approved authoritative plan.
  79: It must keep that state stable through the engine call (e.g. a host transaction/lock or
  80: appropriate version reservation). Authorization deferred until context exit is too late:
  81: SQLite may already have committed. Host and component transactions are separate; there
  82: is no distributed rollback protocol. Production must define commit/failure recovery.
  83: 
  84: The gateway compares the provider's returned scene and full context against the expected
  85: context, rejects unapproved or stale plans, checks existing assignment asset/scene identity,
  86: and delegates inside the provider's context lifetime. Engine handles reviewed digest,
  87: expected revision, idempotency conflicts and first-review concurrency transactionally.
  88: 
  89: This is a dependency-injected trusted execution boundary, not a security sandbox. There
  90: is no engine authorization callback. A malicious provider can lie, and direct Engine
  91: calls remain available for backward compatibility. Do not expose the raw Engine or let
  92: end users choose providers, grants, mappings or authenticated identity. A production host
  93: must enforce access control independently; the Protocol cannot prove compliance.
  94: 
  95: ## Errors, staleness and replay
  96: 
  97: Adapter errors use existing DomainError(code, message). Additional codes include
  98: PLAN_NOT_APPROVED, STALE_PLAN, SCENE_MISMATCH, SCOPE_MISMATCH, RESOURCE_MISMATCH,
  99: PRINCIPAL_MISMATCH and HOST_POLICY_DENIED (synthetic provider). Engine errors remain
 100: unchanged. Readiness receives the current approved binding and returns Engine blockers;
 101: a changed binding yields STALE_SCENE_BINDING without silently rebinding assignments.
 102: A newly current plan requires explicit assignment revision and fresh review.
 103: 
 104: Every replay rechecks current host context and policy first. For rights reviews, ARE-A1's
 105: idempotency payload contains rights identity/content and ReviewRequest, but not scene
 106: context. If authorization still succeeds under a later approved scene context, an exact
 107: rights review replay returns the original event; it does not append history or restore
 108: an old rights revision's approval. Assignment review replay includes the exact scene
 109: binding/usage and therefore cannot reuse a changed plan's binding. Altered review payloads
 110: under one key conflict. Two competing decisions produce one success and one conflict;
 111: which decision wins is intentionally unspecified.
