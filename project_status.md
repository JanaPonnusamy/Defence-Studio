## F1 implementation notes

F1 added a standalone Python/FastAPI package under `backend/defence_studio`; it does not import QVault or Whisper Studio. SQLite is authoritative at `DEFENCE_STUDIO_DB_PATH` (default `data/defence_studio.sqlite3` under the project root). Bootstrap creates schema version 1 with additive `CREATE TABLE IF NOT EXISTS` statements, WAL mode, foreign keys, and bounded busy timeout. Unsupported schema versions fail closed. No prior Defence Studio application database existed to migrate.

The API derives `owner_id` from a verified HS256 bearer token. Configure a random `DEFENCE_STUDIO_AUTH_SECRET` of at least 32 bytes and an external trusted token issuer. F1 does not issue tokens or register users. Job creation is idempotent by `(owner_id, Idempotency-Key)` and a canonical payload digest. SQLite `BEGIN IMMEDIATE` plus a unique constraint serializes concurrent duplicates. The thirteen persisted stages preserve the design pipeline order; stage execution cannot begin until its predecessor is completed or skipped. Transition history stores UTC times/errors. Artifact references are append-only versioned rows scoped to `jobs/<job_id>/` with a schema version and caller-supplied SHA-256.

F1 itself did not include a worker. F2 adds an opt-in durable worker engine and startup recovery while keeping the API worker loop and all production handlers disabled. No feed provider, download, AI service, rendering, artifact byte store/checksum verification, full auth integration, or Phase 1 execution is enabled. See `backend/WORKER_CONTRACT.md` for the F2 guarantees and limits.

## F3 implementation and verification

F3 adds a content-acquisition engine (`defence_studio.acquisition`) plus a path-safe artifact byte store (`defence_studio.storage.artifacts`), running only as the handler registered for the locked `topic_search_and_source_collection` worker stage — no HTTP endpoint, no synchronous execution. It acquires real bytes for explicit, already-approved targets (http(s) pages/PDFs and YouTube subtitles/captions only, never full video) through an SSRF-guarded fetcher (`url_guard.py`/`http_client.py`) that blocks loopback/private/link-local/reserved addresses on every resolved address and every redirect hop. Declared, source-supplied metadata is preserved with an explicit `COLLECTED`/`UNAVAILABLE`/`NOT_COLLECTED` status per field — nothing is fabricated. Acquisition is idempotent (hash-verified reuse of already-stored sources, including across a worker retry after a simulated crash) and reports explicit partial success across multiple targets; one target's failure never substitutes a different source. Full field-level contract in `backend/CONTRACTS.md`; QVault components inspected/adapted and those deliberately not reused are in `backend/SOURCE_PROVENANCE.md`. Implementation review remains the release gate before Phase 1A/1D or any downstream phase.

## F4 implementation and verification

F4 adds a deterministic, stdlib-only analysis layer (`defence_studio.analysis` + `defence_studio.contracts.analysis`) running only as the handler registered for the locked `extraction_validation_normalization_deduplication` worker stage — no HTTP endpoint, no AI/paid-API call. It reads F3's real `acquisition_manifest` artifact, independently re-verifies each referenced byte artifact's SHA-256 before trusting it, normalizes HTML/subtitle/plain text without stripping qualifiers/negations/dates/units/designations, deduplicates sources (same-URL, identical-content, and threshold-based near-duplicate text) while preserving every original source record, extracts verbatim claim spans with exact offsets (never a paraphrase, never asserted as true), flags cross-source conflicts for human review without merging either side, and writes one versioned, content-addressed `analysis_result` artifact. A strict schema-validation seam (`ai_schema.py`) exists for a future AI-assisted extractor but is not wired to any provider in this phase. Full field-level contract in `backend/CONTRACTS.md`; no QVault/Whisper Studio source was reused (`backend/SOURCE_PROVENANCE.md` F4 section). Implementation review remains the release gate before Phase 1D or any downstream phase.

During implementation, two real bugs were found and fixed before marking F4 complete, not just test bugs papered over: (1) a test-fixture helper was double-writing bytes for an "ACQUIRED" source even when the test intended to override its artifact list afterward, silently replacing a deliberately-deleted/corrupted file and collapsing an intended `ARTIFACT_UNREADABLE` case into `ARTIFACT_CORRUPT` — fixed in the test, not the service. (2) a genuine service bug: `run_and_store`'s content-addressed output path was keyed by input identity, but the serialized artifact still embedded a wall-clock `analysis_timestamp`, so two runs over byte-identical inputs produced different file contents (and therefore different SHA-256) at the same path — contradicting the claimed idempotency guarantee. Fixed by adding a check-before-write short-circuit: if an artifact already exists at the computed input-digest path, it is reused as-is rather than rewritten, mirroring the check-before-reuse pattern F3 already uses for its own idempotent re-acquisition.

F3 landed as real, complete code (not a placeholder) partway through this session — `defence_studio.acquisition` with `http_page`/`youtube_subtitles` providers, `build_acquisition_handler`, and its own passing test suite — so F4 was wired against the actual F3 output contract rather than a guessed one. Two concrete mismatches were caught and corrected during wiring: the real F3 manifest artifact type is `acquisition_manifest` (not the `acquisition_result` initially assumed before F3 landed), and real per-source byte artifacts are typed `source_content`/`source_subtitles` with schema `defence-studio.source-artifact.v1` (not `raw_page`/`raw.v1`). `ACQUISITION_RESULT_ARTIFACT` in `contracts/analysis.py` was corrected to match F3's real constant, and one end-to-end test (`test_real_f3_acquisition_output_feeds_real_f4_analysis_through_worker`) drives the actual `build_acquisition_handler` (via a mocked HTTP transport, no live network) and the actual F4 handler back-to-back through the same F2 `Worker`, proving the wiring against real F3 code rather than only a hand-built fixture.

## Phase 1A implementation and verification

Phase 1A adds feed discovery as the handler for the locked `news_feed_and_topic_discovery` worker stage (the stage already reserved for it between `application_foundation` and F3's `topic_search_and_source_collection` — no stage renaming or reordering was needed). It discovers *candidate* sources for an owner-approved topic and never acquires content itself; F3 remains the only stage that fetches full bytes.

**Request submission**: `POST /api/jobs/{job_id}/discovery/requests` validates a topic/language/search-terms/filters/limits payload (`defence_studio/contracts/discovery.py`) and writes it as a `discovery_request` artifact against the `application_foundation` stage — which has no handler of its own — via a new, narrowly-scoped `JobService.add_pretransition_artifact` (allows an artifact on a not-yet-started stage, but only while the job is still `DRAFT`, so there is no worker-claim race). Submitting identical content again is idempotent (same artifact version reused); submitting after the job is queued or discovery has started is rejected `409`. The owner still queues the job themselves through the existing endpoint.

**Providers**: `rss_feed` (works without credentials once `DEFENCE_STUDIO_DISCOVERY_RSS_FEEDS` is configured; reports `UNAVAILABLE_NOT_CONFIGURED` otherwise, never silently returning nothing) and `configured_search_api` (requires `DEFENCE_STUDIO_DISCOVERY_SEARCH_API_URL`/`..._KEY`; reports `UNAVAILABLE_MISSING_CREDENTIALS` and makes no network call when unset). Both reuse F3's existing `UrlGuard`/`GuardedFetcher` — no new SSRF surface. One provider failing never blocks the others (`ProviderOutcome` per provider, explicit partial success).

**Ranking and dedup**: deterministic, explainable scoring (`defence_studio/discovery/ranking.py`) from topic/term overlap, recency (neutral 0.5 when no date is available — never fabricated), language match, and source-type preference, each with a human-readable explanation line. Deduplication is canonical-URL-only (reusing F3's `normalize_url`), so two providers returning the identical URL are merged with provenance of both kept, while distinct publishers with merely similar titles are always kept as separate candidates.

**Selection → F3 handoff**: `GET /api/jobs/{job_id}/discovery/candidates` (filterable) and `POST .../discovery/selection` (validates known/non-duplicate candidate IDs and that discovery has completed) build an `acquisition_request` artifact that F3's real `defence_studio.contracts.acquisition.request_from_dict` parses unmodified — verified directly in `tests/test_discovery_f1a.py::test_select_candidates_produces_f3_compatible_acquisition_request`, not just asserted in prose. Re-selecting the same candidates reuses the existing artifact version (content-hash idempotency, same pattern F4's output uses). Discovery never marks a candidate acquired/verified/approved; only F3's own worker claim does that.

**Frontend**: a new "Discovery" tab in the existing `frontend/` static app (`frontend/js/views/discovery-view.js`, registered as F1A-V1) — request form, provider-outcome chips, ranked candidate cards with an expandable "why this ranking" explanation, checkbox selection, and a confirm action, reusing the existing text-field primitive (UI-01) rather than introducing a new one. Loading/empty (no discovery run yet)/error states are handled; an unauthorized job renders the same 404-driven error state the Sources/Claims tabs already use.

**Tests**: `tests/test_discovery_f1a.py` — request validation (empty topic, invalid limit, malformed/reversed date range, unknown provider, topic text never reworded), provider behavior (missing-config/missing-credential reporting with zero network calls, topic keyword matching, partial success across multiple feeds), deterministic ranking and neutral-not-fabricated missing-date scoring, canonical-URL dedup versus distinct-publisher preservation, SSRF-guard reuse (a feed resolving to a blocked address is rejected), full runs through the real F2 `Worker` (missing-request fail-closed, successful run, simulated lease-expiry retry), and the API-facing service (idempotent request resubmission, cross-owner `DiscoveryNotFound`, conflict once discovery has started, selection validation, the discovery-to-F3 contract handoff, cross-owner candidate-listing denial via `TestClient`). 26 new tests. Phase 3 turns an **approved** Phase 2 evidence package into a human-reviewable, source-grounded narration script (Tamil and/or English), requires an explicit human approval of a specific revision, and exposes that approved revision as a stable Phase 4 input contract. **Engine reuse, not duplication.** `defence_studio.services.script.ScriptService` subclasses the Phase 2 `EvidenceService` (itself a subclass of F5's `ReviewService`), reusing its job-ownership checks, `ArtifactStore` access, JSON-artifact integrity verification, and package assembly/approval-ledger logic. A live provider call only happens on an explicit authorized `POST .../script/generate`, never on a read, package inspection, job creation, or review.

**Fail-closed generation.** Generation revalidates the evidence package immediately before the provider call: the current snapshot must be `ready` and match a row in the `evidence_packages` approval ledger whose stored artifact is genuinely `APPROVED`. A missing/unapproved/stale package, a review change after approval, or corrupted evidence bytes all block generation before any provider spend (tested). A duplicate `(job_id, language, Idempotency-Key)` replays the existing revision (no second revision, no double-spend). Provider failures (timeout/rate-limit/malformed/missing-key) raise `ScriptGenerationFailed` (HTTP 502) and write nothing, so a retry is safe. A measured cost over the configured `max_text_cost_inr` fails closed.

**Evidence integrity, not model self-judgement.** `services/script_validation.py` (deterministic, pure) requires every material-fact section to cite ≥1 approved, eligible claim that exists in the package with an in-package supporting source, forbids a citation ID appearing inside spoken narration, and requires a title + closing. ERROR issues force `VALIDATION_FAILED` (un-approvable); the machine-readable evidence mapping is stored separately from spoken narration so citation IDs are never voiced. The validator never asks the model to confirm its own output.

**Immutable, independent, explicitly-approved revisions.** Schema v5 (`database.py::_upgrade_v4_to_v5`, additive) adds immutable `script_revisions` (`PRIMARY KEY(job_id, language, version)`) + append-only `script_review_history`. Tamil and English are independent lineages — approving one never approves the other; approving a new revision supersedes the prior approved revision **of the same language only**. Approval runs in `BEGIN IMMEDIATE`, binds to the exact `revision_sha256`, refuses a validation-failed/already-approved/superseded revision, re-checks the revision's package is still the current approved evidence, requires a non-blank note, and replays idempotently. `export` returns the approved revision only while its evidence remains current — a clean Phase 4 input contract.

**Word count / duration** is a deterministic whitespace count over spoken text only, yielding an explicit duration *estimate* (`words-per-minute.v1`, `is_estimate: true`), never presented as an exact recording time. **Cost** is computed from a stored INR pricing table × a configurable USD→INR rate with `cost_is_measured` distinguishing measured from unavailable; the ₹10/video target is measured, not asserted.
