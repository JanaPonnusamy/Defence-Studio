# Defence Studio backend foundation

Python 3.11+, FastAPI, SQLite. From this directory, install `pip install -e ".[test]"` and run `pytest`. Start the API with `uvicorn defence_studio.api.app:app --app-dir . --host 127.0.0.1 --port 8010`.

Before startup set `DEFENCE_STUDIO_AUTH_SECRET` to a random secret of at least 32 bytes. The API accepts HS256 bearer JWTs from a trusted issuer that shares this key and provides a string `sub` plus numeric `exp`; F1 does not implement user registration or token issuance. Set `DEFENCE_STUDIO_DB_PATH` to the authoritative SQLite database path for this server. The default is `data/defence_studio.sqlite3` under the project root. Do not point it at QVault's database.

Create a job with `POST /api/jobs`, an `Idempotency-Key` header, and `{ "topic": "...", "language": "ta" }`. The owner comes only from the verified bearer token. Read with `GET /api/jobs/{job_id}`. Queue an eligible new job with owner-authenticated `POST /api/jobs/{job_id}/queue`; repeating the request is idempotent. Stage transitions use `POST /api/jobs/{job_id}/stages/{stage_key}/transitions`; failures require an `error`. Artifact references use `POST /api/jobs/{job_id}/artifacts`. URIs are relative references; F1 records a supplied SHA-256 and schema version but does not write or validate artifact bytes.

SQLite `schema_info` is version 2. A version-1 F1 database receives an additive, exclusive-transaction migration that preserves jobs, transitions and artifacts while adding queue timestamps, retry metadata and persistent worker claims. Unsupported schema versions fail before application-table DDL. API startup recovers expired claims; it does not start a worker. `defence_studio.services.worker.Worker` runs only an explicitly supplied handler map, and every registered handler must be named in the `retry_safe_stages` set passed to the constructor; a handler that is not declared retry-safe, or a declared stage with no handler, fails closed at construction time. F2 registers no production handlers and does not enable feed providers, feed scheduling, downloads, AI services, rendering or artifact byte storage. Handlers with external effects must use the supplied deterministic stage idempotency key or reconcile effects before retry; exactly-once external execution is not guaranteed. See `CONTRACTS.md` and `WORKER_CONTRACT.md` for transition, claim, lease and retry rules.

From this directory run `python -m pytest -q` for the backend suite. The test suite uses temporary Defence Studio SQLite files; set `PYTHONDONTWRITEBYTECODE=1` when using a shared Python environment.

## F3 content acquisition

F3 adds a reusable Content Acquisition module that runs only as a handler registered for the `topic_search_and_source_collection` worker stage — it has no HTTP route and never runs synchronously inside a request. Given an `AcquisitionRequestV1` (read from the stage's input `acquisition_request` artifact), it acquires real bytes for each approved target through a guarded fetcher and writes one `AcquisitionResultV1` manifest artifact (`acquisition_manifest`) referencing the exact stored bytes.

Set `DEFENCE_STUDIO_STORAGE_PATH` to the filesystem root that physically holds acquired bytes (default `data/storage` under the project root); artifact URIs recorded in SQLite remain the relative `jobs/<job_id>/...` references this root resolves against.

Two providers ship: `http_page` (generic http(s) page/PDF download; declared `<title>`/publisher/published-time/language only, no article extraction) and `youtube_subtitles` (subtitles/captions only — never the video — via yt-dlp; install the optional `youtube` extra, `pip install -e ".[youtube]"`, for live use). Every outbound request is SSRF-guarded by `defence_studio.acquisition.url_guard.UrlGuard`: non-http(s) schemes, embedded credentials, and any URL resolving to a loopback/private/link-local/reserved address are rejected, including on every redirect hop. Downloads are size- and time-bounded; bytes land under the configured storage root through `defence_studio.storage.artifacts.ArtifactStore`, which rejects any path escaping `jobs/<job_id>/`.

Acquisition is idempotent: repeating a request for a source whose stored artifact still exists and hash-matches reuses it instead of re-downloading, including across a worker retry after a crashed attempt. Multi-target requests report explicit partial success — one target's failure never blocks the others, and a failed target is never silently replaced by a different source.

See `CONTRACTS.md` (F3 contract section) for the full field-level request/result schema and `SOURCE_PROVENANCE.md` for which QVault components informed this design and which were deliberately not reused.

## F4 source analysis, normalization & evidence extraction

F4 adds a deterministic, stdlib-only processing layer (`defence_studio.analysis`) that runs only as the handler registered for the locked `extraction_validation_normalization_deduplication` worker stage. It reads the real `acquisition_manifest` artifact F3 wrote for the predecessor stage, re-verifies each referenced byte artifact's SHA-256 before trusting it, normalizes HTML/subtitle/plain text without destroying meaning (qualifiers, negations, dates, units and designations are never stripped), deduplicates sources (exact URL, identical-content, and configurable near-duplicate text), extracts verbatim factual-claim spans with exact offsets into the normalized text, flags apparent cross-source conflicts for human review, and writes one versioned, content-addressed `analysis_result` artifact. No paid AI service is called or configured; `defence_studio.analysis.ai_schema` is a strict validation seam for a future AI extractor, so malformed AI output would be rejected rather than silently accepted.

Extraction never asserts truth: a claim is the exact source substring plus its provenance, never a paraphrase or a verified fact, and duplicate/claim grouping is a textual relationship only — never corroboration or proof. Output is idempotent — re-running over unchanged inputs reuses the existing artifact at its input-digest path instead of rewriting it, so retries never create spurious duplicate versions. See `CONTRACTS.md` (F4 analysis contract section) for the full field-level contract.
