# Voice Audio Lab / Audio Module (Standalone)

A fully standalone reference-audio ingestion, forced-alignment, acoustic
analysis, performance-profile, performance-planning, and provider-neutral
TTS synthesis service, built strictly from
`DEFENCE_STUDIO_AUDIO_MODULE_FULL_BUILD_SPEC.md`. It has **no dependency**
on any other part of the Defence Studio repository: its own source tree,
config, SQLite database, job system, API, tests, docs, logging, and
storage all live inside this folder.

## Architecture

```
FastAPI app (app/main.py)
  -> app/api/*            REST endpoints (spec section 19)
  -> app/jobs/*            in-process thread-pool job queue + handlers
  -> app/pipeline/*        ingest, normalize, transcript, align, analyze,
                           profile, planner, validate, waveform
  -> app/tts/*             provider-neutral TTS adapter interface +
                           local-pyttsx3 (real) + mock-tts (explicitly fake)
  -> app/db/*              SQLAlchemy models + SQLite persistence
  -> storage/*             module-owned files (audio, transcripts,
                           alignment, analysis, profiles, generated,
                           waveforms, jobs, logs)
```

## Run the tests

```powershell
.venv\Scripts\python -m pytest
```

Tests run against an isolated temp storage root + temp SQLite DB (see
`tests/conftest.py`) so they never touch the real `storage/` directory.

`fixtures/generate_fixture.py` the first time tests run (or manually via
`python fixtures/generate_fixture.py`).

## Honest limitations (read before relying on outputs)

1. **Forced alignment is an approximation, not a measurement.** No
   GPU/neural forced-alignment model (whisperx/MFA/wav2vec2-CTC) is
   installed -- doing so reliably on an arbitrary Windows box without
   internet-fetched model weights was judged impractical for this build.
   Instead `app/pipeline/align.py` implements an **energy/VAD-based
   segmentation + proportional word timing** fallback:
   - If the transcript already carries real cue timing (SRT/VTT),
     segment-level timing is trusted (`quality_label=segment_timed_word_proportional`,
     confidence 0.95) but word-level timing within each segment is still
     only proportional-by-character-length (confidence capped at 0.55).
   - If the transcript is plain text with no timing, segment boundaries
     come from VAD speech-region detection
     (`quality_label=approximate_proportional_vad`, confidence capped
     around 0.4).
   This is reported explicitly in every alignment result's
   `quality_label` and `mean_confidence` / per-word `confidence` fields --
   callers must not treat word timings as phoneme-accurate.
2. **Loudness is an RMS-based dBFS proxy, not ITU-R BS.1770 LUFS.** True
   LUFS metering (K-weighting + gating) was out of scope for this build;
   the field is still named `loudness_lufs` in storage but surfaced to the
   API as `loudness_estimate_dbfs` to avoid overclaiming precision.
3. **Two TTS adapters are provided:**
   - `local-pyttsx3`: REAL local/offline synthesis via the OS speech
     engine (SAPI5 on Windows). `describe().is_mock == False`.
   - `mock-tts`: **DELIBERATELY FAKE.** Produces a short placeholder tone,
     never real speech. `describe().is_mock == True`,
     `provider == "mock-tts"`, and every `GeneratedAudio.provider_metadata`
     it produces carries `"is_mock": true`. Used for testing the full
     pipeline without requiring an OS speech engine or cloud credentials.
4. **Video/URL ingestion is a disabled-by-default stub.** `app/pipeline/ingest.ingest_url`
   requires `feature_video_url_ingest=True` AND explicit
   `rights_metadata.authorized=true`, and even then raises
   `NotImplementedError` -- no actual downloader is implemented, because
   this standalone module cannot verify licensing/platform terms on its
   own (spec sections 4.2, 22). Direct audio upload is the fully
   implemented path.
5. **Pitch/F0 tracking** uses `librosa.pyin` (a real probabilistic YIN
   implementation) -- no `parselmouth`/`pyworld` dependency, since those
   require extra native build steps not justified for this build; pyin is
   accurate enough for the prosody/pitch-contour features in the spec.
6. **Job durability:** the job queue is an in-process `ThreadPoolExecutor`
   (documented in `app/jobs/queue.py`). A `RUNNING` job interrupted by a
   process crash stays `RUNNING` in the DB (no crash-recovery sweep is
   implemented). `QUEUED` jobs are safe to resubmit since no work started.

## Original narration preview (2026-10-15)

The Audio Creator now loads `/tts/delivery-profile`: a versioned, hashed,
original editorial profile (neutral, serious, urgent, calm, documentary).
These presets are not measurements of any reference speaker. Select
`local-pyttsx3`, a language, and an installed voice ID/name from the displayed
inventory. Missing voices and incompatible languages fail closed. The UI
disables generation when the inventory contains no matching language.

Native controls are requested rate (80–260 WPM) and volume (0–1).
Pitch shift (-3 to +3 semitones) uses librosa after synthesis, not native
SAPI pitch. Delivery labels approximate rate/volume; native emotion, exact
pause durations and guaranteed word emphasis are unsupported. Punctuation
is passed to the OS engine. Unicode is NFC-normalized, not transliterated.
For acronyms, supply the desired spoken spelling in the narration text.

Real output metadata includes sample-derived duration, pitch with a pYIN
probability threshold, energy activity, pauses, RMS dBFS (not LUFS), dynamic
range, supplied-text WPM, warnings and SHA-256. These measurements do not
prove pronunciation or emotional naturalness. Compare retained preview
cards, play their audio, and download each configuration/measurement JSON.
Word-level forced alignment is still unavailable; existing proportional
alignment must not be treated as measured timing.

Each pyttsx3 request runs in a separate child process with a 60-second
synthesis timeout. Scratch output is validated before exclusive publication;
unknown voices never fall back to a different-language default. Same-job
queue claims are atomic and terminal job states fence late status updates.
Completed job/artifact persistence across a real server restart was verified.
**Interrupted RUNNING jobs still have no lease/recovery policy.** Do not run
unattended crash retries or manually reset a live job. The standalone API
has no cancellation endpoint or HTTP idempotency-key contract; distinct
POSTs intentionally create distinct jobs. The main Defence Studio voice
workflow has its separate existing worker/cancellation contract.

Install the declared `requirements.txt` into a dedicated virtual environment;
librosa was already declared, so no dependency bypass or production install
is needed. FFmpeg/ffprobe are needed for independent acceptance decoding.
Bind this unauthenticated standalone development service to loopback. Do not
expose it as an authenticated production service.

Tamil remains unavailable on the audited host (Hazel en-GB and Zira en-US
only). No eSpeak NG executable, Tamil OS voice or cloud credential was
provisioned. Select and authorize a Tamil provider, verify its actual voice
inventory and applicable licence, then run real Tamil synthesis and native
speaker listening review before claiming support. No provider/model/system
installation or paid synthesis was performed by this change.

(relative to repository root).

## Rights / Licensing details

Every reference stores a `rights_metadata` JSON blob supplied by the
caller. The module does **not** auto-fetch or assume rights for any URL;
see limitation 4 above. Commercial voice-model licensing is explicitly out
of scope (spec section 12) -- this module analyzes **performance**
(tempo/pause/energy/pitch style), never voice identity/cloning.
